### 문제 1 — 주식소각결정: 감성 오분류 (neutral → positive)

**실제 출력**
```
감성: neutral  영향도: +0
요약: 주식소각결정 보통주식 (주): 종류주식 (주) | 73,359,314: 13,603,461 ...
핵심: 기타 투자판단과 관련한 중요사항 | - 금번 주식 소각 결정은 주주가치 제고 등의 목적으로...
```

**기대 출력**
```
감성: positive  영향도: +1~+2
```

**원인**

주식 소각은 주주환원의 대표적 호재 공시다. 본문에 "주주가치 제고"라는 명시적 긍정 표현이 있지만 `POSITIVE_KEYWORDS`에 해당 키워드가 없어서 규칙 엔진이 잡지 못함.

```python
POSITIVE_KEYWORDS = (
    "수주", "계약 체결", "영업이익 증가", "매출 증가", "흑자전환",
    "배당 확대", "자사주 취득", "실적 개선", "신규 투자", "증설", "hbm",
)
# "주식소각", "주주가치 제고" 없음
```

**수정 방향**

`POSITIVE_KEYWORDS`에 추가:
```python
"주식소각",
"주주가치 제고",
"소각예정",
```

### 문제 2 — 사업보고서: 요약이 최대주주 변동 이력 표

**실제 출력**
```
요약: 사업보고서 (제 57 기) 변동일: 2021.04.29 | 최대주주명: 삼성생명보험㈜ | 소유주식수: 1,263,050,053 | 지분율: 21.16% | 변동원인: 변동전 최대주주의 피상속
핵심: 구 분: 투기등급 | S&P: D | S&P: 금융채무불이행 상태 혹은...  (← 신용등급 참조표가 핵심으로 잡힘)
리스크: 일 자: 1989.08.25 | 변 동: 유상증자 | ...  (← 1989년 역사 데이터)
```

**원인**

사업보고서는 수백 페이지짜리 문서다. 현재 `analysis_max_chars = 6000`으로 앞부분만 자르는데, 삼성전자 사업보고서의 앞 6000자는 최대주주 변동 이력 표와 신용등급 참조표다. 실제 사업 현황(매출, 영업이익, 주요 사업 내용)은 훨씬 뒤에 있다.

추가로:
- 핵심 근거에 `S&P: D` (파산 상태 신용등급)가 잡힘 → 이는 신용등급 설명 표의 최저 등급 예시로, 삼성전자의 실제 등급이 아님
- 리스크에 1989년 유상증자 이력이 잡힘 → 과거 이력 표

**수정 방향**

단기: 사업보고서는 `NEUTRAL_ADMIN_TITLE_KEYWORDS`에 추가해서 분석을 건너뛰거나 제목만 남김. 사업보고서는 정기공시로 분기별 잠정실적 공시가 따로 있어서 토론 컨텍스트에서 중요도가 낮음.

중기: 긴 문서는 앞부분 대신 특정 섹션(손익계산서, 재무상태표)을 우선 선택하는 전처리 필요. `build_filing_chunks()`에서 이미 섹션 분리가 되어 있으므로, 분석 시 Chroma 상위 청크를 활용하는 방향(`evidence-llm-analysis-implementation-plan.md` 9-2절)으로 개선 가능.

### 문제 3 — 최대주주등소유주식변동신고서: 연락처가 요약

**실제 출력**
```
요약: 최대주주등소유주식변동신고서 tel: (fax) | 02-2255-9000: 02-779-8920
```

**원인**

문서 첫 번째 표가 회사 연락처 표다. 실제 내용(변동 주식수, 변동사유, 변동 전후 지분율)은 뒤에 있지만 `first_sentence`가 연락처 표를 먼저 잡음.

이 공시 유형은 최대주주 변동 알림으로 단순 행정 공시에 가깝다. 대부분의 경우 `neutral/0`이 맞지만, 요약이 연락처인 건 문제다.

**수정 방향**

`NEUTRAL_ADMIN_TITLE_KEYWORDS`에 추가:
```python
"최대주주등소유주식변동신고서",
```

또는 `DART_BOILERPLATE_PATTERNS`에 연락처 패턴 추가:
```python
"tel:",
"(fax)",
```

### 문제 4 — 자기주식취득결과보고서: 수신처가 요약 + 감성 neutral

**실제 출력**
```
요약: 자기주식취득결과보고서 금융감독원장 귀하: 회 사 명 : | 2026년 4월 24일: 삼성전자주식회사
핵심: 법제165조의3의 규정에 의한 보유상황(A): 수량 | 비율 | 총가...
감성: neutral  영향도: +0
```

**원인 1 — 요약 품질**

문서 첫 줄이 `금융감독원장 귀하`로 시작하는 수신처 정보. 실제 핵심(취득 수량, 취득 단가, 취득 금액 합계)은 뒤에 있다.

`DART_BOILERPLATE_PATTERNS`에 `금융감독원장 귀중`, `금융감독원장 귀하`는 있지만, 표로 직렬화되면 `금융감독원장 귀하: 회 사 명 :` 형태가 되어 기존 패턴이 매칭되지 않음.

**원인 2 — 감성 neutral**

자기주식 취득 완료는 약한 호재 신호다. `POSITIVE_KEYWORDS`에 `자사주 취득`이 있지만, "취득결과보고서"는 취득이 완료됐다는 보고서라 "결과보고" 텍스트가 `자사주 취득` 키워드와 함께 나오지 않는 경우가 있다.

**수정 방향**

`DART_BOILERPLATE_PATTERNS`에 추가:
```python
"금융감독원장 귀하",   # 표 직렬화 후 패턴
"금융위원회 귀하",
```

감성은 `자기주식취득결과보고서` 제목 자체를 positive 보정 규칙에 추가하는 방향.

### 문제 5 — 임원ㆍ주요주주특정증권등소유상황보고서: 변동 방향 구분 불가

**현재 상태**

대주주 장내 매수(호재)든, 장내 매도(악재)든, 담보권 실행(강한 악재)이든 모두 `neutral/0` 출력.

**원인**

`_serialize_grid` 2단 헤더 문제로 변동 내역 표에서 `변동사유`, `취득/처분` 방향을 꺼내지 못함.

이 문제는 `docs/dart-table-serialization-issue.md`에 별도 문서화되어 있으며, `_expand_table_to_grid`의 span 메타데이터 보존(옵션 1)으로 근본 해결 가능.

현재 하네스가 표 헤더 노이즈를 막고 있어서 `neutral/0`으로 안전하게 처리 중.

## 3. 수정 우선순위

| 우선순위 | 문제 | 수정 방법 | 난이도 | 효과 |

| 2 | 자기주식취득결과보고서 수신처 요약 | `DART_BOILERPLATE_PATTERNS` 추가 | 낮음 | 요약 개선 |

| 4 | 임원보고서 변동 방향 구분 불가 | `_serialize_grid` span 메타데이터 수정 | 높음 | 대주주 매수/매도 구분 가능 |
| 5 | 사업보고서 요약 품질 | Chroma 청크 기반 분석 입력 전환 | 중간 | 핵심 재무 정보 추출 |

## 4. 현재 토론 품질에 미치는 영향

우선순위 1~3은 규칙 몇 줄 추가로 해결 가능하고, 실제 토론에서 자주 등장하는 공시 유형이다.

우선순위 4 (임원보고서)는 대주주 매도 같은 중요 신호를 놓치지만, 현재 하네스가 garbage 요약을 막고 있어서 토론 에이전트에게 잘못된 정보는 전달되지 않는다.

우선순위 5 (사업보고서)는 분기별 잠정실적 공시가 별도로 있어서 사업보고서가 없어도 재무 정보는 토론 컨텍스트에 포함된다.

## 5. 정기보고서 고도화 로드맵 (현재 스킵 → 섹션 타겟팅)

> 현재 사업보고서/분기보고서는 `NEUTRAL_ADMIN_TITLE_KEYWORDS`로 분석 스킵 처리 중.  
> 아래는 향후 필요하다고 판단될 때 구현할 고도화 방향이다.

### 왜 지금 당장 하지 않는가

1. **정보의 후행성**: 사업보고서에 기재된 대규모 수주/M&A/특허 등은 이미 수개월 전 개별 수시공시로 시장에 공개된 재탕이다. 시장은 수시공시 시점에 반응하지, 정기보고서에서 재확인할 때 반응하지 않는다.

2. **파싱 비효율**: 수백 페이지에서 핵심 섹션을 찾으려면 전체 텍스트를 스캔해야 한다. 현재 `analysis_max_chars = 6000`으로 잘라도 앞부분이 주주 이력/연락처 등 비핵심 정보다.

3. **오탐 위험**: "부채 증가", "흑자 전환에 실패하였으나" 같은 문맥을 키워드만으로 잡을 수 없다. 맥락(context) 이해가 필요하다.

4. **수시공시 우선**: 단일판매계약, 잠정실적, 자기주식취득결정 등 주가에 즉각 영향을 주는 수시공시 파싱 품질을 높이는 것이 ROI가 훨씬 크다.

---

### 고도화 시 타겟팅할 4개 섹션

| 섹션 | 내용 | 시그널 |
|---|---|---|
| **II. 사업의 내용** | 수주잔고, 생산설비, 가동률, R&D 진행 | 수주 급증 → positive, 가동률 하락 → negative |
| **V. 이사의 경영진단 및 분석의견 (MD&A)** | 경영진이 직접 서술하는 실적 원인과 전망 | 턴어라운드 확신 → positive, 마진 하락 인정 → negative |
| **XI. 투자자 보호를 위하여 필요한 사항** | 소송, 과징금, 우발채무, 미상환 CB/BW | 주요 피소 + 자기자본 대비 대형 → negative -2 |
| **재무제표 주석 / 감사의견** | 감사의견, 계속기업 불확실성, 대손충당금 | 한정/부적정/의견거절 → negative -2, 계속기업 불확실성 → negative -2 |

### 구현 방향

전체 텍스트를 통째로 읽는 대신 목차를 파싱해서 해당 섹션만 추출한다.

```text
build_filing_chunks() 개선
    ├── 목차(Table of Contents) 파싱
    │       └── 로마자 II, V, XI 섹션 위치 탐지
    ├── 섹션별 텍스트 슬라이싱
    └── 각 섹션을 별도 청크로 Chroma에 저장

EvidenceAnalysisService 개선
    └── 사업보고서 → 섹션 II + V + XI 청크만 분석 입력으로 사용
```

현재 `build_filing_chunks()`가 `## 섹션명` 형태로 섹션을 분리하고 있으므로, 섹션명 필터링으로 구현 가능하다.

### 감사의견 즉시 감지 규칙 (단기 추가 가능)

섹션 파싱 없이도 아래 문구가 텍스트에 있으면 하네스에서 즉시 잡을 수 있다.

```python
CRITICAL_NEGATIVE_PHRASES = (
    "계속기업으로서의 존속능력에 유의적 의문",
    "감사의견: 한정",
    "감사의견: 부적정",
    "감사의견: 의견거절",
)
```

이 문구가 감지되면 `sentiment = "negative"`, `impact_score = -2`로 강제 보정. 상장폐지 위험 신호이므로 분류 오류의 여지가 없다.
