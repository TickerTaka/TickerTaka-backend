# MCP 양방향 E2E 증적 (2026-06-20)

평가 항목6(MCP/A2A) 보완 — 2차 리포트가 "클라이언트 E2E는 키/DB 미주입으로 [S]"로 4점을 준 것에 대해, **실제 환경에서 양방향 모두 E2E 동작**을 캡처한 증적이다.

대상 코드: `app/mcp_server.py`(서버, FastMCP), `app/integrations/notion_mcp.py`(클라이언트, 공식 `mcp` SDK).

---

## 1. 클라이언트측 — Notion 발행 E2E (우리 → Notion MCP 서버)
공식 `mcp` SDK(`ClientSession`/`stdio_client`)로 교체한 `NotionMcpClient.publish_debate`가 **실제 Notion 페이지를 생성**.

요청: `POST /api/debates/e11a0291-e47a-4547-82db-fd5a57df3992/publish/notion`
응답(200):
```json
{
  "session_id": "e11a0291-e47a-4547-82db-fd5a57df3992",
  "notion_page_id": "384bee7e-7ca8-8155-93a9-e28eb99bbe5d",
  "notion_page_url": "https://app.notion.com/p/financial-debate-384bee7e7ca8815593a9e28eb99bbe5d",
  "notion_published_at": "2026-06-20T00:05:12.736509+09:00"
}
```
**멱등 검증**: 동일 호출 재실행 → 새 페이지 생성 없이 **동일 `notion_page_url`·`notion_published_at` 반환**(저장값 그대로). → SDK 교체 후에도 발행+멱등 정상.

**raw 실행캡처(2026-06-21 재현): [reports/notion-publish-e2e-2026-06-21.log](notion-publish-e2e-2026-06-21.log)** — 미발행 세션 `eda4011d-8e11-40f5-a81c-ecd6a7a86acc`(005380)에 대해 라이브 `POST .../publish/notion` 1회 호출로 **실 페이지 `386bee7e-7ca8-81bd-b042-cca40bd163f7` 생성(HTTP 200)**, 2차 호출은 **동일 page_id/url/published_at 반환(HTTP 200)** 으로 멱등 확인. 손으로 정리한 서술이 아니라 엔드포인트 raw JSON 응답 원문.

## 2. 서버측 — 실 외부 MCP 클라이언트(Claude Desktop) → 우리 MCP 서버
Claude Desktop(Microsoft Store/MSIX)에 우리 서버 등록 후 실제 호출.
- `claude_desktop_config.json`(MSIX 경로 `…\AppData\Local\Packages\Claude_*\LocalCache\Roaming\Claude\`)에 `tickertaka` 등록 → Developer에 **running**.
- 대화: "토론 가능한 종목 목록" → `list_available_symbols` 호출 → **24종목 반환**.
- "005380 종목 상세" → `get_stock_detail` → **현대차** 반환.
→ 외부 AI 클라이언트가 우리 도메인 기능을 tool로 실제 호출·데이터 수신.

## 3. 서버 stdio 프로토콜 round-trip (GUI 무관 재현)
`python -m scripts.mcp_selftest` (mcp 클라이언트가 `python -m app.mcp_server`를 stdio로 spawn).
**raw 실행캡처: [reports/mcp-selftest-2026-06-21.log](mcp-selftest-2026-06-21.log)** (run 2026-06-21T15:13Z, commit `3adf311`):
```
tools/list (7): ['list_available_symbols', 'get_stock_detail', 'get_watchlist_feed', 'list_debates', 'get_debate', 'start_debate', 'add_watchlist']
call list_available_symbols → {"count": 27, "symbols": [{"symbol":"000270","name_kr":"기아"}, ...]}
RESULT: PASS ✅
```
서버측 round-trip은 **tools/list 7개 + call_tool(`list_available_symbols`) 27종목 반환**까지 실제 DB 연결 상태에서 통과. (직전 평가는 DB 미연결로 call_tool이 OperationalError였으나, 본 캡처는 DB 연결 E2E.)
